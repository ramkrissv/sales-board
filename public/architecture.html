02 — AI Architecture

AI-Native Intelligence Layer

Every AI call flows through a single gateway with rate limiting, sandbox validation, token budgets, and telemetry. 13 autonomous agents and 12 workshop assists, all server-side, all logged.

AI Call Flow

AI Gateway
src/lib/ai/gateway.ts

03 — Workshop Engine

Assessment & Proposal Engine

McKinsey-grade assessment workflow: score, surface gaps, aggregate scope, write proposals. 9-tab flow, 12 AI assists, clone-on-create templates. Single MongoDB document with embedded framework graph.

9-Tab Workshop Flow

Workshop Data Model
Single MongoDB document with embedded graph:
workshop → framework → levels[] → dimensions[]
 → scores[] → findings[] → scopeItems[]
 → useCases[] → aiInteractions[]

Clone-on-create: engagement inherits full framework copy. Edits never mutate the template.
12 AI assists wired in: each tab surfaces relevant assists contextually.
10+ templates: AI Transformation, Cloud Migration, Data Strategy, Security Assessment, and more.
Assessment Scoring
Maturity scale 0 - 4:
0 Absent 1 Ad hoc 2 Repeatable 3 Governed 4 Optimized
Weighted readiness index: level weights normalize to 1.0. Default: L1=0.30, L2=0.40, L3=0.30.

Gap computation: target - current > 0 triggers scope item generation.

Priority rank: min(3, gap + priority_flag). Drives workstream ordering and proposal emphasis.

Readiness stage: Not Started → Emerging → Developing → Governed → Scaling → Optimized
Deliverable Assets
Assessment Report
Current-state narrative, readiness spine, dimension scores, gap heatmap
Transformation Roadmap
Phased scope, workstream rollup, effort model, dependency map
Architecture Deep Dive
L2 platform assessment, toolkit gaps, integration audit
Executive Briefing
Board-ready 1-pager: index, top gaps, recommended pilots, investment ask
Gap Analysis
Dimension-level gaps with findings, implications, and remediation scope
04 — Guardrails & Observability

Guardrails & Observability

Eight-layer guardrail chain from rate limit to human review. Every AI call traced, metered, and auditable. Budget-capped at $50/day, $500/month.

Guardrail Chain

1 Rate Limit config/rate_limits.json
AI endpoints: 30 rpm, 500 rph, max 5 concurrent
Global API: 60 rpm, 1000 rph
tRPC mutations: 120 rpm, 3000 rph
Export endpoints: 10 rpm, 50 rph
WebSocket: 3 connections/user, 100 msg/min
2 Sandbox Validation gatekeeper/sandbox.config.json
Forbidden in prompts: password, secret, api_key, token
File ops allowlist: src/, tests/, public/, specs/, execution/
File ops deny: .env*, node_modules/, docker-compose.yml
Network allowlist: api.anthropic.com, github.com, *.amazonaws.com
All interactions logged. Human review required on all AI outputs.
3 Token Budget config/token_budgets.json
Daily limit: $50/day · Monthly limit: $500/month
Per-request max tokens:
 Haiku: 2,000 tokens
 Sonnet: 4,000 tokens
 Opus: 8,000 tokens
DAILY BUDGET$50.00
Haiku: ~$0.002/callSonnet: ~$0.02/callOpus: ~$0.08/call
4 Model Routing config → registry → env fallback
Three-tier resolution: config/token_budgets.json model_routing → assist registry default → AI_DEFAULT_MODEL env var.
Never hardcoded at the call site. Gateway resolves model before every call.
5 Telemetry Trace telemetry/traces/YYYY-MM-DD.jsonl
Every AI call traced: id, assist, model, latencyMs, status, inputTokens, outputTokens, workshopId, userId
JSONL format, one file per day. Machine-parseable for audits and tuning.
6 Metrics Aggregation telemetry/metrics/YYYY-MM-DD.json
Daily aggregation: total calls, successes, errors, avg latency per assist:model pair.
Accept rate target: >70% per assist type.
API: harness.getMetrics, harness.getTraces tRPC endpoints.
7 MongoDB Interaction Log workshop.aiInteractions[]
Every workshop AI call persisted as embedded doc: assist, model, input, output, status (PROPOSED/ACCEPTED/EDITED/REJECTED), userId, timestamp.
Queryable for tuning prompts and measuring assist quality.
8 Human Review Accept / Edit / Discard on ALL outputs
AI output always lands as a proposed draft in an editable surface.
User actions: ACCEPT EDIT DISCARD
Final status recorded in AIInteraction. Rejected outputs = signal for prompt tuning.
Never auto-commit AI output without an accept step.
Security
Authentication
NextAuth + Microsoft SSO + TOTP 2FA
Middleware enforcement on all routes
API key server-only (never in client bundle)
Authorization
RBAC: Owner > Lead > Contributor > Viewer
Org-scoped queries on every endpoint
Zod validation on every tRPC procedure

  done_contracts/ → workshop-v1.json

  workflows/ → deploy.yml
  tasks.json

  token_budgets.json → $50/day, model routing, per-request caps
  rate_limits.json → rpm/rph per endpoint type

  sandbox.config.json → file/git/network/AI rules
  approvals/ → human approval records

Agent Personas

Planner
OPUS
Reads specs + ARCHITECTURE.md → writes execution plans. Decomposes features into ordered tasks with dependencies. Outputs structured task lists for the Generator.
Generator
SONNET
Reads plans → writes code. Forbidden patterns enforced by sandbox.config.json. Cannot modify .env, package.json, or docker-compose.yml. Writes to src/, tests/, specs/ only.
Evaluator
OPUS
7-criteria grading rubric: correctness, types, guardrails, tests, patterns, UX, performance. Pass/fail with line-level feedback. Gates the Generator from merging substandard code.
Done Contracts
JSON schemas defining machine-verifiable acceptance criteria per feature. Evaluated by the Evaluator agent against actual implementation.

06 — Deployment & Operations

Deployment & Operations

Docker Compose on EC2 via AWS SSM. Three containers, ~7 minute builds, git-hooks-enforced quality gates. 40+ features across 3 waves.

Deploy Pipeline

1. Push to feature branch
git push origin main:feature/<name> — pre-push hook validates: secrets scan + full TypeScript build
2. SSM command to EC2
AWS Systems Manager sends deploy command to i-085cae314b9dda866
3. Build & deploy
git fetch + checkout + docker compose build + up -d — ~7 minute build cycle
4. Health check
curl https://salespilot.galent.ai — verify 200 response, check container logs
5. Fallback
If SSM fails: aws ec2 reboot-instances → retry deploy sequence
